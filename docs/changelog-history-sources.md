# Источники встроенной истории изменений

История в `AppChangelog.kt` — статические данные внутри APK, без загрузки из сети.
Дата выпуска заполняется только по подтверждённому выпуску; сейчас все даты null.
Время merge, CI или коммита не считается датой выпуска. Записи не утверждают,
что каждому историческому этапу соответствует публичный GitHub Release.

- Ранние этапы: `docs/version-history.md`, согласованная история разделов проекта.
  Сгруппированы без новых номеров и дат, запись явно неполная.
- 1.0.7: тот же документ — топливо/заправки и исправление TimePicker.
- 1.0.8: объединённый PR #33, `docs/harvest-1.0.8-review.md`,
  `docs/main-screen-1.0.8-review.md`; единое завершение дня, продолжение уборки,
  независимые площади, полный общий бэкап, перенос developer block в Options.
- 1.0.9: объединённые PR #35 (расчёты), #36 (календарь), #37 (результаты),
  #38 (ползунки); история изменений добавляется текущим PR. Статус строго
  «В разработке», без даты выпуска. Миграция описана пользовательским смыслом,
  номер Room не используется как номер релиза.

Для добавления версии: добавить ChangelogEntry в начало AppChangelog.entries,
указать уникальный стабильный id, version (или null для этапа), summary и только
подтверждённые непустые категории. releaseDate оставить null до подтверждения.
Обновить JVM-тест порядка; сам экран менять не требуется. BuildConfig.VERSION_NAME
используется только для подписи текущей сборки и начального раскрытия совпадающей
версии. Сейчас он остаётся1.0.8; запись1.0.9 — отдельная будущая версия.
