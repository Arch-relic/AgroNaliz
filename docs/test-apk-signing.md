# Стабильная подпись TEST APK — Issue #27

TEST имеет applicationId `ru.fo6osik.workjournal.debugtest`. Основное приложение
`ru.fo6osik.workjournal`, его подпись и данные не изменяются.

## Причина и предел восстановления

GitHub-hosted runners создавали временный debug.keystore. TEST наследовал debug
подпись: разные runners давали разные сертификаты, а versionCode оставался 1.
Issue #27 сообщает старый сертификат с префиксом 5F3A и новый
9453777AA0F1600B9353F60A39807D7016BE1DCC6095C5D70F2F584F5502BC3A.
Полный старый отпечаток и его приватный ключ не предоставлены. В доступных
рабочих копиях keystore не найден; workflow не сохранял его.
Из APK или публичного сертификата восстановить приватный ключ нельзя.

Не удаляйте установленную TEST, не очищайте её данные и не пытайтесь обойти
проверку Android. Новый ключ не позволит обновить старое приложение на месте.
Если найдётся оригинальный keystore, его полный сертификат надо сопоставить
с установленной APK; только совпадение ключа, совместимая БД и больший
versionCode позволяют обычное обновление. Автоматическое сохранение реальных
данных телефона без этой проверки не обещается.

## Новый workflow

`.github/workflows/test-apk-publish.yml` запускается вручную только владельцем
репозитория из main, только первой попыткой запуска. Код PR и внешних веток
не получает секретов. Сначала отдельный job собирает и тестирует TEST без
ключа. Другой job не делает checkout и не запускает Gradle; inline signer
восстанавливает keystore во временный файл 0600, подписывает APK и проверяет
applicationId, versionCode и полный SHA-256 сертификата. Несовпадение либо
отсутствующая настройка блокируют публикацию. Временные файлы удаляются.

Исходная APK передаётся между jobs внутренним артефактом с пометкой
`internal-unsigned-TEST-do-not-install`, сроком один день; он удаляется после
подписывания, включая ошибку подписывания. Если job не запустился, он истечёт.
Не устанавливайте внутренние APK. Опубликованный результат:
`app-TEST-stable-main-<SHA>-v<versionCode>`, файлы `app-TEST-stable.apk` и
`verification.json` (идентификатор, версия, публичный сертификат, SHA APK,
коммит и Room). Приватные ключи и пароли не публикуются.

Обычный PR workflow сохраняет проверки и main debug artifact, но прекращает
публикацию нестабильно подписанной TEST. Для проверок TEST versionCode равен
1000000 + номер запуска. Для постоянных публикаций — 2000000 + номер запуска
нового workflow, с проверкой предела Android и версии установленной APK.
Параллельные публикации сериализуются; история завершённых запусков блокирует
запоздавшую публикацию меньшего номера. Не переименовывайте workflow и не
сбрасывайте последовательность. При ошибке используйте новый Run workflow,
а не Re-run jobs: повторная попытка блокируется намеренно.

## Обязательные ручные настройки

1. Сохраните старую TEST и найдите старый keystore, если он действительно был
   архивирован. Для нового постоянного ключа используйте защищённый компьютер
   и каталог вне Git, например интерактивный keytool с RSA 3072 и сроком
   10000 дней. Пароли вводите интерактивно; храните резервную копию ключа
   отдельно. Новый ключ не исправляет несовпадение старой установки.
2. В GitHub Settings → Secrets and variables → Actions задайте отдельные
   Secrets `TEST_KEYSTORE_BASE64`, `TEST_KEYSTORE_PASSWORD`, `TEST_KEY_ALIAS`,
   `TEST_KEY_PASSWORD`. Base64 создавайте в приватный файл вне Git и загружайте
   только в Secrets. Не отправляйте ключ в чат и не выводите его в CI.
   Не используйте ANDROID_* основной APK. Пустой TEST_KEY_PASSWORD означает
   пароль хранилища; неверный заданный пароль не подменяется автоматически.
3. Из публичного сертификата выбранного keystore получите полный SHA-256
   через keytool и задайте repository Variable `TEST_CERT_SHA256` — 64 hex
   символа или 32 пары через двоеточия. Конкретный будущий сертификат пока
   неизвестен: ключ и эта переменная не настроены данным изменением.
4. После отдельного одобрения владельцем и merge этого PR в main откройте
   Actions → Publish stable TEST APK → Run workflow → main. Укажите фактический
   установленный versionCode и Room из JSON резервной копии. Значение Room по
   умолчанию 21 консервативно: текущий main содержит 20 и будет заблокирован.
   Для установки с Room 21 нужен совместимый main (PR #26 не объединяется
   автоматически); понижать floor до 20 можно только для подтверждённой БД 20.
5. Скачайте проверенный artifact, распакуйте ZIP и перенесите APK на телефон.
   Сначала сопоставьте certificateSha256 с установленной APK и убедитесь в
   совместимости БД. При несовпадении подписи остановитесь, не удаляйте TEST.

## Безопасное получение существующей копии

Экспорт старой TEST создаёт JSON в приватном `files/test-backups`. Этот JSON
содержит таблицы Room, но не настройки SharedPreferences, произвольные файлы,
медиа и Android Keystore. Это не полная резервная копия приложения. Во время
экспорта не меняйте данные и дождитесь сообщения об успехе.

На своём компьютере с разрешённым USB debugging можно прочитать копию через
`adb exec-out run-as ru.fo6osik.workjournal.debugtest`. Если run-as запрещён,
остановитесь: скрипт не использует root и не обходит защиту. Список имён:

```
adb -s SERIAL shell run-as ru.fo6osik.workjournal.debugtest ls files/test-backups
python3 docs/export-installed-test-backup.py --serial SERIAL \
  --backup-name Agronaliz_TEST_backup_UUID.json \
  --output /PRIVATE-DIRECTORY/test-backup.json --target-room-version 21
```

Каталог результата должен быть вне любого Git checkout. Скрипт только читает
приватный JSON, проверяет формат, основные связи и недопустимое понижение Room,
создаёт новую копию 0600 без перезаписи существующего файла. На телефоне ничего
не удаляется и не изменяется. Копию храните приватно, не загружайте в Git/CI.
Структурная проверка не доказывает полноту реальных данных или успешное
восстановление на конкретном телефоне. Перенос настроек и остальных файлов
требует отдельного контролируемого плана; без старого ключа бесшовного переноса
в этой задаче нет. Сохраняйте прежнюю установку до проверки всех данных.

## Автоматическая проверка

Python тестирует точный inline signer, неверные отпечатки/метаданные, отсутствие
секретов, закрытый режим workflow, последовательность версий, запрет понижения
Room и read-only экспорт. SDK fixture использует только временный тестовый ключ.
В свежем CI эмуляторе после проверки изоляции устанавливаются две APK с одним
тестовым ключом и возрастающими версиями. Проверяется сохранение Room, файлов,
настроек; попытка обновления другим ключом должна вернуть
INSTALL_FAILED_UPDATE_INCOMPATIBLE и оставить данные нетронутыми. Проверяется
экспорт и восстановление синтетического JSON. Это проверка механизма, а не
подтверждение восстановления пользовательского телефона или старого ключа.
