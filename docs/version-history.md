# Версии АгроНализ

Отображаемый номер версии имеет формат `MAJOR.MINOR.PATCH`. Текущий выпуск —
**1.0.8** (подтверждённый MAIN code3000005). В исходниках подготавливается
**1.0.9**, статус «В разработке»; публикация1.0.9 не выполнена. Номер одинаковый для основного приложения и TEST. В TEST рядом с номером
показывается пометка `· TEST`; она не является частью `versionName`.

Правила проекта:

- **MAJOR** — глобальное поколение приложения.
- **MINOR** — крупные функциональные обновления после завершения первоначального этапа разработки.
- **PATCH** — последовательные этапы развития первоначальной версии, включая новые разделы и последующие пакеты доработок.

До отдельного решения о переходе на **1.1.0** продолжается нумерация **1.0.X**.
Новый раздел в первоначальном этапе сам по себе не переводит приложение на 1.1.0.

| Версия | Этап |
| --- | --- |
| 1.0.0 | Создание проекта и главного меню. |
| 1.0.1 | Список техники. |
| 1.0.2 | История ТО и ремонтов. |
| 1.0.3 | Техническая документация и PDF-просмотрщик. |
| 1.0.4 | Список полей. |
| 1.0.5 | Рабочие записи и журнал событий. |
| 1.0.6 | Уборка урожая. |
| 1.0.7 | Учёт топлива и заправок, включая исправление TimePicker. |

Это согласованная история этапов проекта, а не утверждение о наличии опубликованной
APK или тега для каждого номера. Даты ранее выпущенных APK здесь не реконструируются.

## Конфигурация и совместимость обновлений

Единственный номер для сборок задаётся в `app/build.gradle.kts`:
`defaultConfig.versionName = "1.0.9"`. Главный экран использует
`BuildConfig.VERSION_NAME`, а пометку TEST определяет по `BuildConfig.BUILD_TYPE`.
Разметка не содержит копии номера.

`versionCode` — отдельный целочисленный номер для Android. Он не вычисляется
из 1.0.7 и не сбрасывается при изменении `versionName`. Существующие правила
остаются без изменений:

- Основной выпуск: `main-apk-publish.yml`, `3000000 + GITHUB_RUN_NUMBER`,
  Gradle-параметр `mainVersionCode` влияет только на основную debug APK.
- TEST-выпуск: `test-apk-publish.yml`, `2000000 + GITHUB_RUN_NUMBER`,
  параметр `testVersionCode` влияет только на debugTest APK.
- CI preview TEST: `1000000 + GITHUB_RUN_NUMBER` своего проверочного workflow.
  Это отдельная проверочная последовательность, не замена подписанному TEST-выпуску.
- Локальное значение по умолчанию `versionCode = 1` не менялось. Такую локальную
  APK нельзя считать выпуском для обновления уже установленной опубликованной APK.

Защищённые workflow требуют номер выше установленного, ограничивают его диапазон
Android и блокируют публикацию старого запуска после более нового. Для обновления
необходимы прежние applicationId и сертификат, а также отсутствие понижения Room.
Смена `versionName` сама по себе не разрешает обновление с другим сертификатом
или меньшим `versionCode`.

Основной пакет остаётся `ru.fo6osik.workjournal`, TEST —
`ru.fo6osik.workjournal.debugtest`. Room — v24 с явной миграцией23→24. Миграции, пользовательские
данные и механизмы резервного копирования этим изменением не затрагиваются.

Сначала владелец проверяет Draft PR; после отдельно разрешённого слияния выполняет
защищённую сборку TEST, проверяет версию на смартфоне. Выпуск основной APK требует
отдельного решения владельца. Эта задача не публикует и не устанавливает обновления
на пользовательские устройства.

## 1.0.8 — историческая запись подготовки до выпуска

Единое завершение дня с конечным топливом, быстрый доступ к активной уборке,
снимок/фактическая площадь кампании и показатели по завершённым дням. Room23
добавляет две nullable-площади без переноса текущих площадей в историю.
Общий JSON-бэкап адаптирован к Room23. Это изменение исходников, не выпущенная APK.
Android-проверки пока не подтверждены; защищённый выпуск MAIN остаётся заблокирован
до отдельного аудита новой схемы. Детали: [отчёт](harvest-1.0.8-review.md).
