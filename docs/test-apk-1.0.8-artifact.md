## Механизм публикации

Используется существующий test-apk-publish.yml: отдельный build без секретов,
отдельный inline signer без checkout/Gradle, прежние TEST Secrets и pinned SHA256,
проверки package/code/сертификата, очистка временного ключа и внутреннего транспорта.
Основной MAIN workflow, ключи, applicationId и его параметры не меняются.

Добавлен узкий push-trigger только для test-artifact/1.0.8-pr33 и только изменения
самого TEST workflow. Оба jobs требуют repository owner и run_attempt1. PR/fork,
другие ветки, автоматический main push и Re-run не подписывают APK. Прежний ручной
main-выпуск остаётся. Это отдельный разрешённый владельцем выпуск TEST исходников
из PR33; main merge не нужен. Следующий отчётный commit не публикует новую APK.
Счётчик существующего workflow не сбрасывается: code=2000000+run_number.
Для этого push проверочный floor2000006 взят из последнего стабильного выпуска,
а не выдан за считанный versionCode телефона. Floor Room23 исключает понижение
относительно собираемой версии. История завершённых публикаций и concurrency
сохраняют прежнюю защиту порядка.

Перед upload дополнительный gate требует package ru.fo6osik.workjournal.debugtest,
versionName1.0.8, ожидаемый code строго больше2000006, Room23 и исходный SHA.
Сертификат обязан совпадать с указанным последним стабильным TEST. verification.json
помечает installedPhoneCompatibility=NOT_CONFIRMED. При любой ошибке upload не идёт.
Артефакт содержит только app-TEST-stable.apk и verification.json, не ключи/пароли.

## Как проверить установленную TEST непосредственно на смартфоне

1. В уже используемом App Manager выбрать именно «АгроНализ TEST» и сверить пакет
   ru.fo6osik.workjournal.debugtest. В сведениях о версии записать versionName и
   versionCode (обычные настройки Android могут показывать только versionName).
2. В разделе подписи/сертификатов App Manager открыть сертификат установленного
   приложения, скопировать полный SHA-256 —64 hex-символа, а не короткий префикс.
   Это публичные данные; приватные ключи/пароли получать или отправлять не нужно.
3. Сравнить его с certificateSha256 из нового verification.json и убедиться,
   что новый versionCode строго больше установленного. При несовпадении или
   неизвестных данных совместимость не подтверждена: не выполнять обновление.
4. Room можно точно узнать из поля databaseVersion уже доступной JSON-копии.
   Текущий старый TEST не показывает Room отдельной строкой; его резервные копии
   находятся в приватной песочнице и обычный файловый менеджер их не открывает.
   Если доступной копии нет, оставить Room неизвестной; не выдавать предполагаемую
   схему APK за проверенную версию рабочей базы. Для чтения частного JSON есть
   существующий read-only ADB-инструмент, но это отдельное действие владельца.

Не удалять приложение, не очищать данные, не менять защиту TEST-копий и не
использовать root для обхода песочницы. Новый артефакт можно скачать на смартфон
и посмотреть его метаданные в App Manager без установки. Сборка без доступа к
телефону не доказывает совместимость обновления конкретной установки.
