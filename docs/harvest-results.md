# Площадь, масса и урожайность уборки

## Оценка насыпной плотности

`HarvestDensityCatalog` содержит следующие **ориентиры проекта**, кг/м³:

| Культура | Ориентировочная плотность |
| --- | ---: |
| Пшеница | 750 |
| Ячмень | 600 |
| Горох | 750 |
| Подсолнечник | 400 |
| Кукуруза (зерно) | 720 |
| Рапс | 650 |
| Овёс | 450 |
| Рожь | 700 |

Это округлённые типичные значения для сыпучего зерна/семян, а не норматив
приёмки, измеренная плотность конкретной партии или гарантия товарной массы.
Справочные материалы для понимания метода и различий насыпной/истинной плотности:
[Engineering ToolBox — bulk densities](https://www.engineeringtoolbox.com/density-materials-d_1652.html),
[FAO — Grain storage techniques](https://www.fao.org/4/t1838e/t1838e00.htm).
Таблица фиксирует допущения именно этого расчёта; она не заменяет лабораторное
определение натуры зерна. Влажность, примеси, сорт, уплотнение и состояние зерна
меняют реальную плотность. Для массы, используемой при продаже/учёте, нужны весы.

В карточке кампании можно задать положительную дробную плотность вручную,
в том числе после завершения кампании. Кнопка «По справочнику» снимает
корректировку. Для «Другое» справочного значения нет: требуется ручной ввод,
иначе масса и урожайность не вычисляются. При смене культуры ручная
корректировка сбрасывается, чтобы не применять плотность прежней культуры.
Корректировка действует на все дни этого процесса, включая прошлые;
она не является отдельным измерением плотности для каждого дня.

## Расчёт и площадь

`HarvestCalculator` — чистый Kotlin без Android/Room. Сохранены коэффициенты
объёма: FULL [1;1], MORE_THAN_HALF [0,5;1], HALF [0,5;0,5], LESS_THAN_HALF [0;0,5].
Нижняя граница последнего диапазона может быть нулевой — это существующее
допущение оценки объёма, а не сохранённая нулевая площадь.

- Объём = рабочий объём бункера × сумма коэффициентов наполнения.
- Масса, т = объём, м³ × плотность, кг/м³ / 1000.
- Урожайность, т/га = масса / фактически убранная площадь.
- Урожайность, ц/га = масса × 10 / площадь.

Каждый расчёт выполняется для обеих границ диапазона. Неизвестные/невалидные
исходные данные не подменяются нулём; деление на ноль и нечисловые результаты
не допускаются. Количество бункеров учитывает все записи, а не только FULL.

Площадь необязательна при завершении дня. Пустое поле сохраняет `null`;
положительные дробные значения принимаются с точкой или запятой. На втором
шаге сохраняется прежний вопрос о завершении всей кампании; отмена любого
шага ничего не записывает. Площадь и завершение дня сохраняются в одной
транзакции с необязательным завершением кампании. Завершённый день позволяет
добавить, изменить или очистить площадь, не открывая день/кампанию снова.
Редактирование площади меняет только это поле. Запись Room выполняется
в фоновом потоке; после неё карточка загружается заново.

Итоги кампании суммируют объём/массу всех её дней и отдельно известные площади.
Если хотя бы один день имеет неизвестную площадь (включая активный день),
общая урожайность не рассчитывается и выводится предупреждение. При полных
данных используется отношение суммарной массы к суммарной площади,
а не среднее арифметическое дневных урожайностей. Обычно до двух десятичных знаков
в представлении не означает лабораторную точность оценки.
Малые положительные значения, округляющиеся в ноль, показываются с дополнительными знаками.

## Данные и совместимость

Room v21: миграция 20 → 21 добавляет nullable REAL
`harvest_days.harvestedAreaHa` и `harvest_processes.bulkDensityKgM3`.
`bulkDensityKgM3 = null` означает использование справочника, если культура
известна; историческую площадь миграция не угадывает. Другие колонки,
индексы, связи, настройки напоминаний и события после бункера не меняются.
Destructive migration отсутствует.

Полные резервные копии v18–20 восстанавливаются в v21 с прежними допустимыми
пропусками колонок таймера/событий и двумя новыми nullable-полями. Копия v21
должна содержать все колонки. Выборочный импорт продолжает принимать v16,
v18, v19 и v20, а также v21, с существующей дедупликацией по UID.
Новые поля участвуют в экспорте, восстановлении и импорте; неизвестные
legacy-значения остаются null. Отрицательные/нечисловые новые значения
отклоняются, полный restore проверяет их до замены записей.

## Автоматическая проверка миграции

CI собирает настоящую базовую TEST APK с main-коммита
`c0ea3d01a97dd0eb4814b59307b44169916821bc` (Room v20). В одноразовом
Android API 35 эмуляторе `HarvestMigrationTest.seedV20` создаёт синтетические
записи через стабильный API/SQL и копию v20. Затем `adb install -r` обновляет
TEST APK до результата PR с тем же applicationId/отладочным ключом.
Room проверяет всю схему при открытии v21. Тест сравнивает все старые значения
всех таблиц, настройки таймера, события и FK, а затем восстанавливает копию v20.

`docs/run-harvest-checks.py` вызывается после существующей проверки изоляции.
Он отказывается работать на физическом устройстве или заменять уже
установленную TEST-версию. Основная синтетическая версия проверяется до/после
удаления TEST. Эти скрипты предназначены только для свежего эмулятора CI.

Ручные проверки перед выпуском: удобство диалогов на небольшом экране/с
крупным шрифтом, десятичная клавиатура конкретного телефона, реальные
таймеры/напоминания при блокировке экрана и агрономическая сверка с весами.
TEST APK: `ru.fo6osik.workjournal.debugtest`; основная APK:
`ru.fo6osik.workjournal`. Новая функциональность не меняет их изоляцию.
