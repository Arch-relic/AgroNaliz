# Влажность и отдельный учёт топлива

Room21→22 добавляет только nullable harvest_days.moisturePercent и новые
harvest_fuel_days/harvest_refuelings с FK дня/техники и уникальными UID.
Никаких DROP, пересоздания пользовательских таблиц или destructive migration.
Существующие площадь/плотность/таймеры/бункеры/события сохраняются.

Влажность0..100% либо null хранится у каждого дня. При завершении она
необязательна; отмена второго вопроса о кампании не меняет данные. Кнопка
«Влажность урожая» позволяет изменять/очищать её, в том числе в закрытой
кампании. Расчёты массы/урожайности и пользовательская плотность не меняются.

Краткие результаты показывают реальные диапазоны объёма/массы/т/га,
известную площадь; неизвестные значения — «—». Нулевой известный расход,
объём или число бункеров остаются нулём. При неполной кампании указан
статус и число дней, участвовавших в урожайности, расчёт прежний.

Иконка колонки справа от начала/конца открывает «Топливо за день».
Показания сохраняются отдельной кнопкой; заправки — отдельными записями,
не событиями таймера. Несколько записей можно изменять и удалять с
подтверждением. Время HH:mm необязательно. Все уровни0..100%, после
заправки не ниже до. Расход = начало + сумма приростов DAY − конец,
на гектар делится только при известной положительной площади. Не хватает
показаний — «—»; отрицательный расход — предупреждение без выдуманного нуля.
Проценты датчика приблизительные, это не измеренные литры.

BEFORE_DAY — явно введённая заправка между сменами перед указанным днём,
закреплённая его постоянным dayUid. Она исключается из суммы DAY, потому
что новое начало уже содержит заправленное топливо. Показания предыдущего
дня не переносятся; рост начала не считается ошибкой и не создаёт запись.
Техника фиксируется при первом сохранении дневного топлива, с FK и
снимком названия. Смена комбайна у кампании не перепривязывает историю.
При явном удалении техники FK становится null, снимок и записи остаются;
при обычном повторном открытии/завершении дня все записи сохраняются.

Полная копияv22 включает новые таблицы; старые18–21 принимаются с
документированными отсутствующими колонками/таблицами. Полное восстановление
имеет прежнюю явную семантику замены всей базы выбранной копией. Merge import
старого файла не стирает уже введённые влажность/топливо; новые записи
сопоставляются через day/vehicle maps, refuelUid исключает дубликаты.
Проверки диапазонов и FK выполняются до commit, ошибки откатывают transaction.

## TEST на телефоне

PR-проверки после добавления guard сохраняют только диагностические отчёты,
без публикации основной debug APK; ключ TEST не меняется. Существующий постоянный
TEST signer разрешён только владельцу/main; из непроверенной feature-ветки
ключ не используется. Поэтому сначала Draft PR/CI, затем только по отдельному
решению владельца merge и Actions → Publish stable TEST APK → main,
указав реальные установленные TEST versionCode/Room. Текущая цельRoom22.
Скачать verified app-TEST-stable-main-* artifact и app-TEST-stable.apk.
Нужны прежний постоянный TEST keystore и совпадение TEST_CERT_SHA256 с
установленной TEST. Если ключ старой TEST недоступен, обновление другим
ключом невозможно: не удалять её/данные. Подробности docs/test-apk-signing.md.
Обычная debug main APK из CI не предназначена для установки обновления.
