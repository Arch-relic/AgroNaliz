## Почему подготовка APK остановлена

1. main-apk-publish.yml допускает подпись только owner/main/первую попытку.
   Он собирает github.sha текущего main, то есть1.0.7, а не head PR33.
   Существующая инфраструктура не предусматривает подписанный pre-merge MAIN
   artifact из feature-ветки. Merge запрещён; обход защиты не выполнялся.
2. Его preflight требует room==22 и завершает Room23 сообщением
   `New Room version needs a separate verified migration audit`.
   Тест test_room23_main_publication_remains_blocked намеренно сохраняет запрет.
   В этом этапе он не ослаблялся.
3. Требуемый точный сценарий MAIN1.0.7/Room22→MAIN1.0.8/Room23 с существующим
   топливом/влажностью/активной уборкой отсутствует в MAIN runner. TEST22→23 и
   MAIN20→23 дают полезные, но не равнозначные доказательства. Не объявлять
   сохранность всех данных такого MAIN обновления подтверждённой.
4. Установленные на реальном телефоне MAIN metadata не предоставлены; известна
   последняя опубликованная APK. Нельзя обещать обновление неизвестной установки.
5. Совпадение сертификатов MAIN/TEST требует учитывать буквальное ограничение
   задания; отдельный сертификат для MAIN несовместим с требованием прежней подписи.

Подписанной MAIN1.0.8, её versionCode, APK SHA256 и release verification.json нет.
[Машиночитаемый отчёт BLOCKED](main-1.0.8-verification.json) имеет apkSha256=null,
а не выдуманный checksum или подтверждение выпуска. Временного установочного
MAIN артефакта не публиковалось.

## Продолжение и риски

Перед подготовкой MAIN нужны отдельный точный MAIN22→23 disposable прогон,
сравнение всех legacy/harvest таблиц, активных статусов, топлива/влажности/бункеров/
событий, preferences/files/timers и restart; backup restore в отдельной базе;
далее отдельно проверенный pre-merge путь подписи исходников PR33 через оригинальный
MAIN signer с сохранением pin/guards. Нельзя просто заменить22 на23 или открыть
подпись всем PR. Нужны фактические публичные metadata установленной MAIN; ключи/
пароли не нужны. Новое состояние Secrets подтверждается только разрешённым signer.

До решения этих вопросов выпуск остановлен по прямому условию пользователя.
Потенциальная утрата данных не наблюдалась: реальные данные не использовались.
Главный оставшийся риск — выдать частично покрытый сценарий/неподходящую подпись
за гарантированно безопасное обновление. Физические устройства/OEM не проверены.
Никаких merge/main push, установки, удаления/очистки базы, destructive migration,
релиза, смены подписи/id или раскрытия секретов не выполнялось.
