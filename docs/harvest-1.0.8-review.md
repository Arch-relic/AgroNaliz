# АгроНализ 1.0.8: уборка и общий JSON-бэкап

Дата: 16 октября 2026. Статус: Draft PR #33 создан; Android-сборка подтверждена
в GitHub Actions. Основной CI упал на быстром доступе: реализация не полностью
проверена. Полный результат инструментальных проверок приведён ниже. Не выпускать и не устанавливать APK
на пользовательское устройство на основании этого отчёта.

## Что уже работало

DatabaseBackupManager экспортировал все пользовательские таблицы через SELECT *,
включая harvest_processes, harvest_days, harvest_bunkers, harvest_fuel_days,
harvest_refuelings, поля и технику. Поэтому существующие столбцы дней (таймеры,
плотность/режим, гектары, влажность, статусы), события бункеров и топливо уже
попадали в общий JSON. Отдельный формат и отдельная кнопка уборки не нужны.
Полное восстановление уже использовало транзакцию и foreign_key_check.
Объединяющий импорт уже сопоставлял processUid, dayUid, bunkerUid, refuelUid,
а топливный день — с единственным рабочим днём. При совпадении сохраняются
существующие данные, не импортируются изменения поверх них. Этот порядок сохранён.

## Найденные проблемы и изменения

1. Окно завершения дня не принимало конечное топливо. Теперь время (существующий
   24-часовой TimePicker), гектары, влажность и конечное топливо сохраняются через
   HarvestDayCompletion в одной Room-транзакции с возможным завершением кампании.
   saveEndLevel обновляет только endPercent, сохраняя startPercent, технику и заправки.
   Пустые поля — NULL. Предзаполнение не округляет сохранённые дробные значения.
2. Быстрый доступ загружает IN_PROGRESS из Room в onResume и повторно при нажатии.
   При нескольких кампаниях обязателен выбор; после выбора статус/активный день
   читаются снова одной транзакцией. Завершённая/удалённая кампания не открывается.
   SharedPreferences, уведомления и напоминания для этой кнопки не добавлялись.
3. createProcess снимает FieldEntity.areaHa в транзакции. Фактическая площадь
   первоначально равна снимку; отдельное редактирование работает и после завершения.
   Существующий редактор карточки не перезаписывает новые площади.
4. Площадь уборки суммируется только по завершённым дням, неизвестные значения
   подсчитываются отдельно. Диапазоны массы берутся из HarvestCalculator.
   Отображаются обе урожайности, остаток, прогресс, предупреждение о превышении.
   При неполной массе урожайности не выдаются за точные; при неполной площади
   не вычисляются остаток/прогресс/урожайность по убранной площади. Масса включает
   текущий день; это явно подписано при активном дне. Урожайность по всей площади
   продолжающейся кампании обозначена предварительной. Нулевые знаменатели безопасны.
5. Совместимость полного восстановления была ограничена Room22; объединяющий импорт
   после смены текущей версии пропустил бы Room22. Добавлены Room23 и перенос двух
   площадей с NULL для старых копий. Набор поддерживаемых старых версий не расширен:
   полное восстановление 18–23; объединяющий импорт 16,18–23 (17 не поддерживалась).
6. Экспорт теперь читает все таблицы в одной транзакции: связанные записи не могут
   попасть в JSON из разных состояний. В полном восстановлении CONFLICT_ABORT
   заменяет REPLACE: дублирующий ключ отклоняется с откатом, а не заменяет другую строку.
7. До восстановления/импорта проверяются структура уборочных таблиц, уникальность
   идентификаторов, родители, статусы, согласованность dayUid топлива. Коллизия UID
   с другим родителем в существующей базе отклоняется. Повторный корректный импорт
   сохраняет существующие строки. Некорректные ссылки отклоняются без изменений;
   корректные NULL-ссылки сохраняют резервные названия из снимков.
8. В разделе общего резервного копирования явно указана «Уборка». Защита частных
   TEST-копий сохранена. Read-only инструмент копирования уже существующего TEST
   JSON понимает Room23 и проверяет новые площади; не создаёт копий на устройстве.

Все типы уборочных записей уже имеют устойчивый идентификатор; новая схема UID
не требуется. Будущие столбцы автоматически экспортируются общим SELECT *, но
их объединяющий импорт потребует отдельного обновления сопоставления и тестов.

## Миграция

Room22 →23, зарегистрированная MIGRATION_22_23:

```sql
ALTER TABLE harvest_processes ADD COLUMN fieldAreaSnapshotHa REAL;
ALTER TABLE harvest_processes ADD COLUMN actualPlantedAreaHa REAL;
```

У существующих записей оба значения NULL. Текущая площадь справочника не переносится
в историю. Остальные таблицы, строки, индексы и внешние ключи миграция не изменяет.
Destructive migration, очистка или восстановление пользовательской базы не запускались.

## Ручная проверка в «АгроНализ TEST» после успешного CI

Выполняет владелец после отдельного разрешения на TEST-обновление, с прежним
сертификатом, более высоким versionCode и без удаления/очистки установленного TEST.

1. Через существующий общий экран сохранить TEST-копию до обновления. Записать
   количества кампаний/дней/бункеров/заправок, активный день, влажность и таймеры.
2. После согласованного обновления проверить те же записи и статусы. У старых
   кампаний обе новые площади неизвестны. Проверить технику и начальное топливо.
3. Создать поле 120 га и кампанию. Проверить снимок/фактическую 120; изменить поле
   на 130 — снимок кампании остаётся 120. Установить фактическую площадь 95.
4. Внести массу 150 т через бункеры и плотность (например 20 полных бункеров по
   10 м³, плотность 750 кг/м³); завершить день с 60 га. Проверить 63,2%, 35 га,
   1,58 т/га и 2,5 т/га. На 90 га изменяются только зависимые показатели.
5. Внести начальное топливо 80%, заправку 30→90% в смене и конечное 55%.
   Расход 85 процентных пунктов; начальное и заправки сохранены. Отдельно
   проверить пустое конечное топливо и влажность 0/100, ошибку >100, отмену.
6. Повторно открыть/редактировать завершённый день: гектары, влажность, топливо
   доступны. Изменить гектары — карточка пересчитывается. Снять площадь/плотность
   у части дней — видна неполнота. Проверить превышение площади и отсутствие деления
   на ноль. Изменить фактическую площадь уже завершённой кампании.
7. На главном проверить 0/1/несколько IN_PROGRESS, прямой переход к активному дню,
   карточку без активного дня, выбор кампании, сохранение кнопки после конца дня,
   исчезновение после конца последней кампании. Повторить после перезапуска TEST.
8. Создать один общий JSON и проверить наличие уборки. Полное восстановление
   проверять только в отдельной тестовой установке/базе с синтетическими данными,
   не в рабочем TEST с ценными записями. Сравнить связи, статусы, расчёты и таймеры.
   Merge выполнить дважды; новые дубликаты не появляются, местные правки сохраняются.
   Старую поддерживаемую копию и повреждённый файл также проверять отдельно.
