# Тестовая APK через GitHub Actions

Workflow: [.github/workflows/android-pr-checks.yml](../.github/workflows/android-pr-checks.yml).
Он сохраняет Android Debug-сборку, JVM-тесты, проверку каталога и диагностические
отчёты. APK публикуется только после успешного завершения этих проверок.
Отсутствие APK завершает шаг публикации ошибкой. Исходный код приложения,
Room, PDF, индексы и пользовательские данные этим workflow не изменяются.

## Запуск и выбор ветки

- Pull Request в main: автоматическая проверка merge-коммита PR.
- Push в main: автоматическая сборка актуального коммита main.
- Actions → Android PR checks → Run workflow → Use workflow from:
  выбрать main или другую ветку, затем Run workflow. Checkout использует
  выбранную ветку; main не зафиксирована в шаге checkout.

Новые настройки main начнут действовать после слияния этого PR владельцем.
До слияния APK доступна из проверки самого PR. Ручной запуск выбранной ветки
использует версию workflow в этой ветке: публикация доступна лишь там,
где присутствует этот шаг.

Артефакт: app-debug-<ветка>-<12 символов SHA фактически собранного коммита>.
Символы вне A–Z, a–z, 0–9, точки, дефиса и подчёркивания заменяются дефисом.
В PR SHA относится к merge-коммиту, а не обязательно к head-коммиту ветки.
Внутри ZIP находится app-debug.apk. Срок хранения — 14 дней.
Диагностические отчёты сохраняются отдельно по прежним правилам.

## Скачивание и установка на телефон

1. В браузере телефона войти в GitHub с доступом к репозиторию.
2. Открыть репозиторий → Actions → Android PR checks → успешный запуск.
3. В разделе Artifacts выбрать app-debug-… и скачать ZIP.
   Если мобильная страница скрывает раздел, включить «Версия для компьютера».
4. Распаковать ZIP файловым менеджером и открыть app-debug.apk.
5. При запросе Android разрешить установку неизвестных приложений только
   выбранному браузеру/файловому менеджеру, затем установить на тестовое устройство.

APK имеет debug-подпись, не предназначена для релиза. Ключ подписи на разных
CI runners может отличаться. При несовместимой подписи не удалять приложение
с рабочими данными: использовать отдельное тестовое устройство/профиль либо
организовать согласованную подпись отдельной задачей. Изменения идентификатора
приложения и постоянное хранение ключей в этом этапе не предусмотрены.
Автоматическая сборка не заменяет ручную проверку установки и экранов.
Состав документов определяется существующими assets в Git; отсутствующие
оригинальные PDF не добавляются в APK автоматически.
