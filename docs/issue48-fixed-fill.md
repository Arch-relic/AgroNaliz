## Безопасный переход

Новая формула напрямую интерпретирует старые коды как1/2/3/4четверти. Сначала
суммируются четверти, затем умножение на вместимость: нет округления отдельных
бункеров. FULL=1, HALF=.5, MORE_THAN_HALF=.75, LESS_THAN_HALF=.25.

Это изменение производной функции, не массовый UPDATE. Однократность перехода
обеспечивается отсутствием преобразования сохранённых значений: после обновления
все результаты используют новую функцию, повторное открытие/restore ничего
повторно не умножает. Не требуется migration marker, новая колонка, Room25 или
миграция. Все даты/время/события/площади/плотности/связи/ID остаются прежними.

Приоритет расчёта — реальное значение CombineSpec связанного комбайна согласно ТЗ.
Если карточка недоступна/не содержит допустимого объёма, используется сохранённый
исторический снимок кампании (например, после удаления техники). Это уже введённое
значение, не новая константа. Read resolution не переписывает ни карточку, ни старые
записи. Новая кампания получает снимок реальной ТТХ автоматически.
Без обоих значений — неизвестный объём/масса, сообщение в UI, без константы4.7.
Существующий механизм заполнения ТТХ NOVA в карточке техники не изменялся;
коэффициенты не зависят от марки/модели. Пользовательские объёмы не подменяются.

Совместимость результата Range(min,max) сохранена для остальных потребителей,
но все вычисляемые границы равны. UI форматирует одно значение, неожиданный
интервал показывает как неизвестный, не как среднее. Объём/масса до3знаков,
урожайность/площадь по прежнему правилу до2; внутренние числа не округляются.
Number+unit защищены общим ReplacementSpan в карточке кампании, дня и бункера.
Если количество целиком шире карточки при крупном шрифте, только соответствующее
значение прокручивается горизонтально: размер шрифта и полный текст сохраняются.
Коды/поля JSON backup не изменены: старая копия восстанавливается с теми же строками
и затем рассчитывается по новой функции. Старые APK при чтении тех же данных
покажут старую формулу; downgrade не является способом отмены перерасчёта.

## 27.10.2026 — решение владельца по карточке результатов (TEST на смартфоне)

сетке 2×2**: первый ряд — «Площадь» и «Бункеры», второй — «Масса урожая» и

ячеек, но в верхней сетке не отображались значения площади, бункеров и массы;
урожайность и подробная статистика присутствовали. Это дефект отображения,
**не подтверждение потери данных**. Для его проверки в отдельной feature-ветке

Расчётные формулы, Room24, резервные копии, версия APK, подписи и защита main
не меняются. Историческая политика прокрутки чрезмерно широких чисел в других
