# APK с оригинальным ключом AndroidIDE

GitHub Actions `Android PR checks` сохраняет debug и отдельную TEST APK и
добавляет артефакт `app-original-signed-<ветка>-<SHA>-v<versionCode>`.
Основная applicationId: `ru.fo6osik.workjournal`; TEST:
`ru.fo6osik.workjournal.debugtest`. Подписанная основная APK — проверенная
debug APK, переподписанная оригинальным ключом, без изменения её содержимого,
функций, Room, миграций или данных. Это не отдельная release-конфигурация.

## Доверенный контекст

Секреты отсутствуют в задании Gradle/тестов. Отдельное задание `original-signature`
запускается только после успешного `android`, на push/main, ручном запуске
для main либо в одобренном владельцем PR из **этого же репозитория** с веткой
`feature/original-key-signing` и владельцем в роли автора/инициатора.
Последний случай нужен для проверки первоначального Draft PR до слияния.
Другие PR, включая внешние fork PR, получают только обычные проверки;
`pull_request_target` не используется. Ручной запуск для произвольной
feature-ветки не получает подписанную APK.

В задании подписания нет checkout репозитория, Gradle, запуска APK или кода
приложения. Оно использует официальный Android SDK и скачивает только main
debug APK из успешного задания этого же запуска. applicationId и versionCode
проверяются до и после подписания. Внешний PR не может получить Secrets через
исправление условия: платформа не выдаёт repository Secrets fork PR, а
штатный workflow дополнительно запрещает такой контекст.

## Ключ и проверка

Используются только уже настроенные repository Secrets:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

Если последний Secret отсутствует/пустой, применяется стандартное поведение
apksigner: пароль приватного ключа равен паролю keystore (типично для PKCS12).
Расшифровка ключа всё равно проверяется SDK. Для отдельного пароля требуется
ANDROID_KEY_PASSWORD; явно заданный неверный пароль не заменяется автоматически.

Keystore восстанавливается в TemporaryDirectory внутри RUNNER_TEMP с правами
каталога 0700 и файла 0600. Пароли передаются инструментам через env-ссылки,
не строками команд. stdout/stderr keytool/apksigner захватываются, ошибки
выводятся без значений Secrets и алиаса; публикуется только публичный SHA-256
сертификата. Временный ключ удаляется finally и дополнительным always cleanup.
Ключ не передаётся в Gradle, Git или артефакты.

`--v1-signer-name ORIGINAL` предотвращает попадание секретного алиаса в имена
META-INF файлов. Оригинальная публичная часть сертификата входит в APK, как
требуется Android; приватный ключ и пароли туда не входят. V1/V2/V3 включены,
V4 sidecar выключен. Старые debug-подписи заменяются, проверка требует ровно
один сертификат через `apksigner verify --print-certs`.

Полный SHA-256, уточнённый владельцем в формате 32 пар байтов:

`3FE57967C15F81EE39EA2B9B88DD96A7506C1B5B9032606ECBEA04BBDB15EE3C`

Pin хранится в workflow, не вычисляется из подписанной APK как ожидаемое
значение. Неполный/невалидный pin, неправильная applicationId/versionCode,
ошибка ключа/пароля, несколько сертификатов или несовпадение SHA-256 завершают
задание ошибкой. Подписанная APK остаётся во временном закрытом каталоге до
полной проверки; в выходной каталог переносится только после совпадения.
При ошибке она не публикуется. Обычные debug/TEST артефакты независимы.

Артефакт содержит только `app-original-signed.apk` и безопасную
`verification.json`: applicationId, versionCode, SHA-256 сертификата/APK,
SHA исходной проверенной сборки. В нём нет keystore, паролей или алиаса.

## Версия и установка обновления

Локальная обычная сборка по умолчанию сохраняет versionCode=1. Публичное
Gradle-свойство `ciVersionCode` позволяет задать целое 1..2100000000.
Actions использует номер запуска, а workflow_dispatch/main поддерживает
необязательный ввод `version_code`. Это метаданные установки, не секрет.

Для обновления нужны одновременно та же applicationId, тот же сертификат и
versionCode не ниже установленного. Если AndroidIDE-сборка имела более высокий
номер, следующий ручной запуск main надо выполнить с подходящим version_code.
Проверить установленный номер можно в сведениях приложения/выводе
`adb shell dumpsys package ru.fo6osik.workjournal` без изменения данных.

1. Открыть успешный Actions run, выбрать **app-original-signed-***.
2. Скачать ZIP, извлечь `app-original-signed.apk`, проверить verification.json.
3. Открыть APK на телефоне и разрешить установку из выбранного источника, если
   Android запросит это. Должно предлагаться **обновление** основной версии.
4. Основное приложение не удалять, не очищать его данные. Не использовать
   обычную app-debug.apk или TEST APK как замену подписанного обновления.

При конфликте подписи/понижении versionCode остановить установку и проверить
отпечаток действительно установленной APK и номер версии. Удаление приложения
не является решением этой задачи. Фактическую установку на личном телефоне
CI не выполняет; совпадение сертификата проверяется автоматически.

После слияния владельцем: Actions → Android PR checks → Run workflow → main.
Либо сборка выполнится на push/main. Для initial PR разрешён описанный выше
строго ограниченный owner preview; промежуточные private signing files
никогда не публикуются.
