## Изменения и архитектура

Все 20 pdfSha256 перенесены из docs/pdf-sha256-local.txt ветки feature/pdf-sha256,
коммит eeca56b6cd2f421fe2af520c4916ef18271f684e, blob
66fea21d7af5f010b96a1208acbb4fb169b6e15f. Список сохранён без изменений.
Сопоставление только по полному пути: app/src/main/assets/ плюс pdfPath
источника assets. Наборы совпали 20/20; basename и порядок не использовались.
Сравнение JSON с main подтвердило изменение только pdfSha256. documentId,
title, revision (все null), searchIndexSha256, sources и пути сохранены.
Поисковые JSON, production-код, UI, Room и зависимости не изменены; PDF не добавлены.

Python-валидатор требует полный набор, lowercase SHA-256 длиной 64, уникальность
путей и хешей в этом конкретном наборе, точную связь путь/хеш. Удалено требование
null-хеша для отсутствующего PDF. Если PDF доступен, хеш сверяется потоком по
8192 байта. Для индексов проверяются хеши байтов, v4/normalized_page,
положительные уникальные номера страниц, строковый текст, смещения UTF-16
(как в Kotlin) и конечные координаты от 0 до 1. Проверено 1535 страниц индексов,
309111 слов. PDF-байты проверены: **0/20**.

DocumentCatalog.validate сохраняет поддержку неизвестных хешей в общей модели;
обязательность 20 значений проверяется репозиторным Python-валидатором.
DocumentCatalog.load читает только индексы, не большие PDF. Фабрика,
DefaultDocumentRepository и публичные операции LocalDocumentStore используют
Dispatchers.IO; PDF копируются и хешируются блоками 8192 байта.
DocumentIntegrityValidator вызывается store внутри IO до активации.
AssetsDocumentSource передаёт ожидаемые метаданные без вычисления или подмены.
Добавление хешей не переносит IO на главный поток. Production-код не менялся.

Добавлены JVM-регрессии: известный хеш при null revision без открытия PDF;
16 MiB синтетического потока с проверкой размера блоков и фонового потока;
обязательная integrity validation даже при совпадении обоих хешей.
Эти JVM-тесты пока не скомпилированы и не запущены.

## Ограничения и риски

Оригинальные PDF отсутствуют. Хеши взяты из списка, не пересчитаны здесь по
оригиналам. Сам список не связывает PDF с текстом, страницами и геометрией
индекса. Структура индекса и совпадение числа страниц не доказывают текстовую
идентичность или правильную подсветку.

Теперь при появлении PDF store может активировать пару с совпавшими хешами
и успешной структурной проверкой. Отдельного признака доказанной семантической
совместимости контракт не имеет. ReadyOffline и CURRENT не являются таким
доказательством. AndroidDocumentIntegrityValidator проверяет диапазон страниц
через PdfRenderer и открывает первую страницу, но не сравнивает текст и не
рендерит все страницы. Runtime-проверка с оригиналами не выполнена.

При прямом использовании синхронного integrity validator caller должен выбрать
фоновый поток; через store он уже работает на IO. JVM-регрессии используют
синтетические данные и подменённый валидатор, не заменяют оригиналы и пока
не запускались. Первый assets download всё ещё выдаст FileNotFoundException:
хеши не добавляют файлы и не подключают провайдеры. Прежние ограничения store
(один процесс, отсутствие fsync каталогов, квоты и автоочистки после crash)
сохраняются. Конфигурация проекта ради обхода ошибки среды не менялась.
