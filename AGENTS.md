# Инструкции Codex для проекта «АгроНализ»

Репозиторий: `Arch-relic/AgroNaliz`. Основная ветка: `main`.
Эти инструкции действуют для всего репозитория. Явные ограничения текущего
задания имеют приоритет, особенно запреты на изменение кода и публикацию.

## Сохранение результатов и передача контекста

После завершения каждой задачи разработки создавай или обновляй
`docs/codex-handoff.md`. Включай отчёт в те же изменения, что и результат задачи.
Пиши на русском языке, так, чтобы другой экземпляр ChatGPT мог продолжить
работу без истории разговора Codex. Заменяй заполнители шаблона фактическими
данными; неизвестные сведения явно обозначай, ничего не придумывай.

Обязательные разделы отчёта:

1. Дата и название этапа, цель и текущий статус.
2. Краткое описание выполненных задач и существенных архитектурных решений.
3. Полные пути созданных, изменённых и удалённых файлов относительно репозитория.
   Если удалений нет, укажи это явно.
4. Текущая ветка, опорный коммит main и SHA проверенного результата.
   Различай закоммиченные и незакоммиченные изменения. SHA должен обозначать
   реально проверенный коммит; не пытайся записать в файл хеш самого содержащего
   его коммита. Если отчёт сохранён следующим коммитом, объясни эту разницу.
5. Команды сборки/тестов, их результаты, число тестов и ошибок. Различай новый
   запуск тестов и UP-TO-DATE; не называй непроведённые проверки успешными.
6. Ошибки, ограничения, непроверенное поведение и риски.
7. Незавершённые задачи и рекомендации для следующего этапа.
8. Номер, URL и состояние Pull Request. Если PR нет, укажи причину.

Не включай пароли, токены, приватные ключи, персональные данные, содержимое
локальных PDF и иные секреты. Используй только безопасные метаданные и
репозиторные пути, не локальные пользовательские пути. Не публикуй реальные
привязки личного хранилища, SAF URI или данные аккаунта.

## Ветка и Draft Pull Request

- Перед новой задачей проверь git status и актуальный origin/main. Сохраняй
  незавершённую работу; при необходимости используй отдельный worktree.
- После завершения согласованной задачи подготовь отдельную feature-ветку и
  Draft Pull Request с кодом и отчётом. Публикация входит в обычный процесс,
  если текущая задача её не запрещает и доступ к GitHub предоставлен.
- Если конкретное задание запрещает коммиты, push или PR либо требует отдельного
  согласования, сначала доведи разрешённую работу до проверяемого результата,
  затем запроси разрешение на запрещённые действия и дождись ответа.
  Не считай общее правило публикации отменой конкретного запрета.
- Перед коммитом проверь итоговый diff, отсутствие посторонних файлов/секретов
  и результаты необходимых проверок. В PR укажи цель и ограничения изменений,
  результаты проверки и ссылку на отчёт в этой feature-ветке.
- После создания PR обнови отчёт его номером и URL, сохрани эту корректировку
  в той же feature-ветке и проверь, что PR остаётся Draft.
- Не объединяй PR с main автоматически и не отправляй изменения прямо в main.
  Для слияния требуется отдельное явное указание пользователя.

## Сохранение приложения и проверки

Сохраняй существующую функциональность. Не изменяй действующие экраны, Room,
зависимости, поисковые индексы или документы за пределами согласованной задачи.
Отсутствие исходных PDF не оправдывает вымышленные хеши, ревизии или подмену
рабочих документов тестовыми. Тестовые данные держи только в тестовых ресурсах
или временных каталогах.

Для задач с изменением Android-кода используй подготовленную облачную среду:

```bash
source /workspace/agronaliz-env.sh
agrogradle :app:assembleDebug :app:test
```

Если окружение недоступно, запиши точную причину и невыполненные проверки.
Для изменения только документации достаточно проверки содержимого и diff;
повторная сборка Android не обязательна. Не меняй конфигурацию проекта ради
проверки, если это не входит в задачу.

## Как основной чат получает результат

Источник передачи контекста — `docs/codex-handoff.md` в GitHub. Пока PR не
объединён, отчёт следует читать из head feature-ветки или через PR, а не из main.
После слияния он доступен в main. Перед продолжением другой экземпляр ChatGPT
должен прочитать отчёт и проверить актуальное состояние репозитория.

Эти файлы не создают автоматических уведомлений, не запускают другие чаты и
не предоставляют им доступ к GitHub. Чат с подключённым доступом к репозиторию
может прочитать отчёт по ссылке без ручного копирования его текста.
